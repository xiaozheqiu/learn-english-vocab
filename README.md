# 背单词 · Oxford 5000

线上地址：<https://xiaozheqiu.github.io/learn-english-vocab/>

移动优先的 Oxford 3000 / 5000 词表（PWA）：4955 个单词，按 A1–C1 分五级，常用短语另立
一栏；按等级 / 档位 / 牛津官方词表 / 词性 / 首字母筛选与搜索，逐条标记「已掌握」，默认全部
在本机浏览器完成；可选的[跨设备同步](#跨设备同步可选)登录后才用云端，不配就是纯本地应用。

一个单词只占一行：多个词性并列写在词性栏里（`arm  n., v.(C1)`），词性来自更高等级时
标注它的等级。旧数据里同一个词按词性分成 2~4 行，在只显示「单词 + 词性」的词表里，
`bank` 这类同词性跨等级的行看起来就是同一条重复了两遍。

布局是三段式：顶栏与筛选 / 板块进度 / 表头固定在顶部，分页固定在底部，只有中间的词表在滚动。

> v3.0.0 起应用收回到「词表」这一个职责：**PIN 锁屏 → 移除**，**学习节奏设置 → 移除**，
> **复习与练习（含 FSRS 排期、抽题、顽固词）→ 移除**。历史数据里的「已掌握」标记原样保留，
> 旧路由能平滑落地，见 [数据](#数据)。
>
> 之后「学习面板」也收掉了：**数据分区（导出 / 导入 / 清空）→ 移除**，
> **设置分区（每页条数 / 默认等级）→ 移除**。面板只剩一张「关于」，
> 顶栏图标从齿轮换成 `i`。理由与边界见 [为什么没有设置面板](#为什么没有设置面板)。

技术栈：TypeScript（strict）+ Tailwind CSS + shadcn/ui + IndexedDB（`idb`）。

## 本地开发

```bash
npm install
npm run dev          # 启动 Vite（数据已是最新时不会重复转换）
```

`npm run data` 把 `data/*.js`（`window.OX.A1 = [[...]]`）转成 `src/data/*.json`。这一步是**增量**的：
产物比源文件新就直接跳过，`dev` / `build` 挂在前面也不会每次重转。改了 `data/*.js`
之后会自动重转，想强制重来用 `npm run data -- --force`。数据源只有这一份。

源数据是 5 元组 `[单词, 词性, 中文释义, 3000/5000, 序号]`，转出的 JSON **只留前两项**。
后三项在前端没有任何读取方：释义不显示也不参与搜索（查词交给三方词典），序号与
3000/5000 从未进过 UI，主键也只用单词和词性。整包搬进分包曾经让五个等级合计 250KB、
还要进 PWA 预缓存，裁掉后是 93KB（-63%）。需要释义照样读 `data/*.js` —— 审计脚本
和重抓牛津义项都以它为源。

产物的「新鲜」判定除了比 mtime，还校验每行是两列。只比时间的话，字段改窄之后老 JSON
依旧算「更新」而永久跳过，表现为本地删了、线上还是旧的。

Vite 以 `host: true` 启动，终端会同时打印 Local 与 Network 地址，手机 / 平板连同一个 Wi-Fi
打开 Network 那条即可在真机上试。

## 校验

```bash
npm run typecheck    # tsc --noEmit
npm run test         # vitest（算法层纯函数，171 个）
npm run test:e2e     # 浏览器回归（Playwright，三个套件 119 项断言）
npm run build        # data + typecheck + vite build（含 PWA）
```

### 测试只在本地跑

CI（`.github/workflows/deploy.yml`）**只做构建和部署**，不跑任何测试：

```
npm ci → npm run build（含 tsc --noEmit）→ 上传 dist → 部署 Pages
```

「类型错误会让部署失败」是唯一保留的质量闸门——它本来就是 `vite build` 前的一道防线，
不是额外的测试步骤。vitest 与 e2e 都留在本地，提交前自己跑。

**不要给 CI 加 `--omit=optional`**：vite 8 的 bundler（rolldown）原生二进制
就在 `optionalDependencies` 里，跳过它构建会直接失败（实测 `Cannot find native binding`）。

### 浏览器回归的两条硬规则

`e2e/` 下的脚本不是为了「跑绿」，所以定了两条规则：

1. **不为让流程跑通而绕过被测行为。**
   如果某一步本该发生却没发生，就让它失败。绝不「帮它把前置条件补齐」。

2. **断言查结构，不查文案。**
   查 `[role="row"][data-key]` 的数量、`aria-pressed`、`data-*`、URL hash —— 不查
   「已掌握」「全库掌握度」这类会随文案调整而变的字符串。文案改动不该让测试变红，
   行为改动才应该。

为此 UI 上留了一批**语义钩子**（不是给样式用的）：

| 钩子                                                                           | 位置     | 用途                             |
| ------------------------------------------------------------------------------ | -------- | -------------------------------- |
| `data-testid="word-grid"` + `aria-rowcount`                                    | 词表     | 行数与就绪判定                   |
| `data-row-index`                                                               | 词表行   | 分页跳转后的序号校验             |
| `data-testid="scope-progress"` + `data-scope` / `data-mastered` / `data-total` | 板块进度 | 当前板块的掌握数与总数           |
| `data-testid="filter-trigger" / filter-mode / filter-done / filter-reset`      | 筛选     | 抽屉交互                         |
| `data-testid="filter-pos" / filter-initial`                                    | 筛选抽屉 | 词性与首字母两组按钮             |
| `data-pos`                                                                     | 词表行   | 该行原始词性标记（供筛选校验）   |
| `data-testid="filter-preview"` + `data-pending` / `data-count`                 | 筛选抽屉 | 草稿是否已提交、按草稿剩多少     |
| `data-testid="bulk-fab" / bulk-mark / bulk-unmark`                             | 批量     | 浮动按钮与动作                   |
| `data-testid="about-sheet"` / `check-update` / `check-update-status`           | 关于     | 面板就绪、手动检查更新           |
| `data-display="word" / "cn" / "revealed"`                                      | 词表行   | 这一行给的是英文、中文还是已揭晓 |
| `data-testid="filter-display" / filter-review`                                 | 筛选抽屉 | 显示语言与「距上次标记」两组     |
| `data-testid="drill-entry" / drill-limit / drill-scope / drill-start`          | 自测     | 入口与出题设置                   |
| `data-testid="drill-question"` + `data-key` / `drill-verdict` + `data-correct` | 自测     | 当前题与判定结果                 |
| `data-testid="drill-pool"` + `data-loading`                                    | 自测     | 能出几题、释义到没到             |
| `data-testid="drill-result"` + `data-wrong` / `data-wrong-key`                 | 自测     | 本轮结果与错词清单               |

三套浏览器回归的分工：

| 套件                 | 覆盖                                                                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `e2e/flow.mjs`       | 词表渲染、掌握切换、筛选抽屉（词性 / 首字母 / 显示 / 复核 / 易混）、中文模式与揭晓、自测全流程与流水、词频序、中文搜索、批量、分页、面板结构 |
| `e2e/edge.mjs`       | 视图跨刷新保留、数据 / 设置分区已移除、滚动位置、深链、桌面布局                                                                              |
| `e2e/pwa-update.mjs` | 新版自动接管 → 无残留提示 → 关于页手动检查更新 → 断网后中文模式仍可用（需先 `npm run build`）                                                |

「不查文案」在中文模式上尤其要守：断言查的是 `data-display` 与行文本里**有没有那个英文单词**，
不是查「看英文」这几个字 —— 后者在窄屏已经被收进图标里了。

`flow.mjs` / `edge.mjs` 里有两组「删干净」断言，专门盯删功能最容易留下的残口：

- **`gone.*`** —— 复习 / 练习 tab、底部导航、旧深链、学习节奏设置都不得存在。
- **`panel.no*`** —— 面板里不得有 tab 分区、导出 / 导入 / 清空的按钮、每页条数与默认等级。

## 数据

IndexedDB 库 `ox5000` **v3**，三个 store：

| store     | key       | 内容                                        |
| --------- | --------- | ------------------------------------------- |
| `mastery` | `key`     | 手动「已掌握」标记（含时间）                |
| `meta`    | `k`       | 显示偏好、迁移标记                          |
| `drills`  | 自增 `id` | 自测作答流水（时间 / 范围 / 题量 / 答对数） |

v3 新增 `drills`，并给它建了 `at` 索引 —— 「最近 N 次」只读尾部几条，不必全表扫。
流水是**追加写、不更新、不删除**的账，只存汇总不存逐题对错：回答「这周比上周记得牢吗」
只需要每次的正确率，逐题对错要先设计一套跨时间对比模型，而这一版还没有用它的地方。

`drills` 里写失败是被**故意吞掉**的（`appendDrill` 的 catch）：自测结果只用于看趋势，
写不进去不该让「刚才那轮白做了」。代价是「历史一直是空的」这类问题不会报错 ——
所以 `db.test.ts` 钉住版本号必须是 3，否则 store 根本不会建、写入全部静默失败。

从 v1 升级时删掉复习遗留的 `srs` / `reviews` / `days` 三个 store，并清掉 `lockEnabled` /
`pinHash` / `lockGraceUntil` / `setupDone` 四个 meta 键 —— 那些数据已经没有界面在读，
留着只会让「这个应用到底存了什么」变得说不清。`mastery` 原样保留。

词条主键沿用旧规则 `等级|单词|词性[|序号]`，所以历史进度零迁移成本：首次启动会把旧的
`localStorage["ox5000-mastered-v1"]` 导入 `mastery`，旧键保留作备份。

隐私模式下打不开 IndexedDB 时降级为内存态，顶栏常驻提示「本次进度不会保存」。

判定分两层（`src/lib/db.ts`）：

- `isMemoryMode()` 同步检查，只能证明「没有 `indexedDB` 这个 API」。
- `probeStorage()` 异步真写一次探针库，才能揭穿「API 在但 `open()` 抛」
  —— Safari 无痕模式就是这种，同步检查会被骗过，导致写入静默落内存、
  界面却没有任何提示。store 初始化时跑一次，失败就把 `memoryMode` 置真。

改这块时注意：只靠同步检查会静默丢数据，`db.test.ts` 里有对应的两条回归。

### 导出 / 导入已移除

界面上的导出 / 导入 / 清空三个动作连同 `lib/db.ts` 里的 `exportAll` / `importAll` /
`parseExport` / `clearProgress`、store 上的 `exportData` / `importData` / `wipeProgress`
一起删掉了 —— 单人本机词表没有换设备搬进度的场景，留着只是一排永远不点的按钮。

代价要说清楚：**界面里没有导出 / 导入 / 清空这三个按钮**。进度活在
IndexedDB `ox5000.mastery` 里，清浏览器数据即归零。备份的正规路径是
[跨设备同步](#跨设备同步可选)（登录后云端有一份）；若要手工搬，从 git 历史里
`git show 542bd98:src/components/Panel/sections/DataSection.tsx` 能捞回整段实现，
`db.ts` 的四个函数同样是纯数据操作、不依赖 UI。

`normalizePrefs` 仍然保留：老库里存着 `sessionSize`、`reviewSize`、`quizSize`、
`retention`、`quizTypes`、`includeExtended`、`cefrCap`、`autoLockMinutes` 这些死字段，
读快照时要归一后写回干净版本。

### 跨设备同步（可选）

手机标记、电脑接着学，靠 Supabase 把「已掌握」对齐。**不配就能不用**：
三个环境变量缺任一时代整块功能不出现，应用与接入之前完全一样（本地开发、e2e、
首次 clone 都是这个状态）。

接入三步：

1. Supabase 建项目 → SQL Editor 跑 `supabase/schema.sql`
2. 仓库 Secrets 加 `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_EMAIL`；
   本地写进 `.env.local`（`deploy.yml` 把它们注入构建，见下面第 4 条）
3. 建唯一的那个账号，然后跑 `./scripts/db.sh -f supabase/set-password.sql`
   把密码落成约定值 —— 不走控制台「重置密码」那套发信流程

本地开发：

```bash
printf 'VITE_SUPABASE_URL=%s\nVITE_SUPABASE_ANON_KEY=%s\nVITE_CLOUD_EMAIL=%s\n' \
  'https://xxxx.supabase.co' 'eyJhbGci...' 'you@example.com' > .env.local
npm run dev
```

**没有「手动同步」按钮。** 同步全自动：点词即推、打开/刷新/切回标签页即拉取合并。
一个需要人催的同步按钮，等于把「设计时没想清楚什么时候该同步」这件事摆在界面上。
登录后同步立刻开始，顶栏会显示「正在与云端同步…」——这条提示不是装饰：慢网络下
一次同步要十几秒，没有反馈时用户会以为点了没反应，去刷新，而刷新恰好重走一遍流程、
此时数据已到位，于是误以为「只有刷新才生效」。

**点开关于面板就预取云端模块。** `supabase-js` 有 210KB，动态 import 意味着第一次
登录要等下载完才能发认证请求。用户点开面板到输完密码之间有几秒，趁这段时间预取，
登录时通常已命中缓存。另外 `pull()` 有 12 秒超时：网络半通不通时浏览器会自己撑到
几十秒，期间界面一直转圈，不如尽早失败并让用户稍后再来（本地数据与队列都不受影响）。

**只有一个账号，所以登录界面只有一个密码框。** 邮箱是构建期注入的常量
（`VITE_CLOUD_EMAIL`），用户在界面上永远看不到它 —— 多用户的注册体系
（邮箱校验、找回密码、账号不存在的区分）服务的是一个不存在的问题。

**注意线上构建必须带这三个变量。** `deploy.yml` 从仓库 Secrets 读并注入，
漏了也不报错：构建会安静地产出一个「纯本地版」，手机端界面看着一切正常，
却连登录入口都没有。这是这块最容易踩的坑。

三条设计约束，改这块之前先读完：

**IndexedDB 是唯一事实来源，云端只是备份。** 所以每个网络调用都由上层 `void`
触发：失败只置状态、不回滚内存、不阻塞渲染。方向反过来（云端失败就回滚本地）
等于让一次断网吃掉用户刚标的词。这条和「隐私模式降级内存态」是同一个取向。

**`pull()` 未登录必须返回 `null`，不能返回空 Map。** RLS 对匿名请求的回应是
空结果集而不是错误（HTTP 200 + `[]`）。把它当成「云端为空」会让合并判定为
「无变化 → 已对齐」，于是登录框永不出现、本机进度永远传不上去。区分这两件事
的责任在 `cloudClient.pull()`：先查会话再查表；`cloud.test.ts` 钉住了这个语义差。

**取消掌握必须落成墓碑行。** 本地只有「已掌握」的键，取消 = 删行。若云端也只存
存在的行，删除就无处可同步：另一台设备拉不到这行，会保留自己本地的标记，
下次 push 又把它复活。所以表里是 `mastered boolean`，取消写 `false`
而不是 `DELETE`。

**时间戳由服务端定。** `updated_at` 由 Postgres 触发器写 `now()`，前端 upsert
时不传。手机和电脑时钟差几分钟是常态，用各自 `Date.now()` 当裁判会出现
「刚标的被旧数据覆盖」。

**标记即同步，但队列要能扛住「点完就关」。** 点一个词就推一次，不让人再点按钮；
推送是 `void` 的异步请求（否则每个词都要等一次网络往返，弱网下没法用），代价是
点完立刻关页面时那次请求可能被浏览器掐断。所以 `lib/pendingPush.ts` 用
localStorage 记一笔「这个 key 与云端不一致」，推成功才销账：

- 页面隐藏 / 关闭 → 原生 `fetch` + `keepalive` 抢救一次（supabase-js 不暴露
  `keepalive`，普通请求在 `hidden` 之后随时可能被丢弃，那正是要救的场景）
- 下次打开 → 启动时的同步会把队列并入回写，顺带消化
- 队列只存 key、不存值，实际状态以 IndexedDB 为准，所以同一个词反复开合
  只留一条，不会出现「先推 true 再推 false」的顺序问题

**销账这一步不能漏。** 踩过一次：弱网下标记的词留在队列里，下次打开虽然被合并
逻辑补推成功、云端也确实有了，但队列没清 —— 于是每次打开都为同一批 key 白推一遍。
`syncRef` 里显式把队列并入 `needPush`，推成的 key 全部 `clearPending`。

`cloud.ts`（轻，含合并规则与 `enabled` 判定）与 `cloudClient.ts`（重，含
supabase-js）是刻意分开的：后者由前者动态 import。supabase-js 约 55KB gzip，
静态引入会让每个没登录的人替它付下载与解析成本 —— 和被移出首屏的 Markdown
解析器（40KB）是同一笔账。合并规则是纯函数，`cloud.test.ts` 逐条钉住；
队列的持久化与降级行为由 `pendingPush.test.ts` 钉住。

免费项目 **7 天无活动会被暂停**，要手动 resume。`.github/workflows/supabase-keepalive.yml`
每 3 天打一次最便宜的查询保活；没配 secret 时静默跳过，fork 不会因此变红。

## 为什么没有设置面板

面板曾经有三个分区：数据 / 设置 / 关于。现在只剩关于，判断依据是「这个分区里有没有
一个用户真的会重复点的动作」：

| 分区 | 原本放的东西                     | 判断                                                       |
| ---- | -------------------------------- | ---------------------------------------------------------- |
| 数据 | 导出 / 导入 JSON、清空进度、安装 | 单人本机词表，不换设备搬进度；清空进度也没人为了重来而清空 |
| 设置 | 每页条数、默认等级               | 每页条数在筛选抽屉里已有一份，等于同一个开关做两遍         |
| 关于 | 词性对照入口、版本号、跨设备同步 | 留着，且把「检查更新」「安装到桌面」挪进来                 |

**每页条数的处理**：抽屉里本来就有一排 `20 / 50 / 100 / 200`，那才是用户改它的地方
（翻页时手就在旁边）。设置页的 select 是同一个值的第二个入口，删掉不损失能力。

**默认等级的处理**：这个确实是唯一入口，删掉后「打开就落在哪个等级」固定为 A1。
但它本来也只是「首次进入没有持久化视图时」的初值 —— 真正用起来之后，
等级由 `ListView` 持久化接管（刷新、切页、从词性对照回来都还原上次的选择），
默认值只在第一次打开或清空存储时露一次脸。为这一次露面在面板里养一个分区不划算。

**安装与检查更新没有丢**，只是搬到了关于：前者是浏览器允许时的一次性入口，
后者回答的正是「我这是不是最新版」，贴着版本号比藏在设置里更合理。

顶栏图标同步从齿轮换成 `i`：面板里已经没有任何可配置项，齿轮会让人点开找设置，
然后发现无处可设。

## 词表视图的状态

筛选条件（等级 / 档位 / 牛津词表 / 词性 / 首字母 / 掌握状态 / 距上次标记 / 搜索词）、
显示语言与排序、页码，是一个 `ListView` 对象，写进 `localStorage["ox5000-list-view-v2"]`。刷新、被系统回收后重进、换标签页再回来
都还原到原来的板块与页。读回时逐字段校验（非法等级、0/负数/NaN 页码、超长搜索词各自
单独回落），坏值不会让整条视图作废。隐私模式下写失败就退回纯内存行为。

抽屉里的条件在按「确定」之前只是草稿，列表不动；关闭抽屉即丢弃。条件从 5 组涨到 7 组之后，
抽屉内容超出 85vh，于是**底部「清空筛选 / 确定」固定在抽屉底栏**、不跟着条件列表滚 ——
否则手机上要先滑过整个字母表才够得着「确定」，「点确定才生效」这个前提就被埋掉了。
板块进度（`A1 已掌握 12 / 900`）分母固定是板块总词数，不吃搜索词与掌握筛选；
搜索时列表跨等级，进度也跟着报全库。

### 为什么筛选里只有一套等级

抽屉里曾经同时有「等级（A1–C1）」和「难度（CEFR）」，那是两套分级做同一件事：
词条级 CEFR 取的是首义难度，而词表自带的 A1–C1 标签本来就是这个意思。
实测两者几乎完全一致，只有 March / May 这类同形异义词（月份 vs 三月）对不上。
用户看到两个下拉，实际筛出的是同一批词。

所以 CEFR 维度整体移除：界面上没了「难度」分区，`Word` 上也不再带 `cefr` /
`senseCefr` 字段，`src/data/cefr.json` 瘦成只保留两个官方标记并改名 `oxford.json`
（425KB → 175KB，预缓存跟着少 197KB）。生成脚本同步改名 `scripts/gen-oxford.py`。

保留下来的业务维度各回答一个不同的问题：

| 维度     | 回答的问题                 | 来源                          |
| -------- | -------------------------- | ----------------------------- |
| 等级     | 这个词在教学大纲里算几级   | 词表原数据的 A1–C1            |
| 学习档位 | 这个词值不值得花时间背     | 词频 + 官方标记（tiers.json） |
| 牛津词表 | 牛津官方清单里有没有这个词 | Oxford 3000 / 5000 标记       |
| 词性     | 这是个什么词               | 源数据第 2 列，归一成 10 大类 |
| 首字母   | 这个词以什么字母开头       | 单词首字符                    |

### 词性筛选为什么只有 10 档

源数据的词性列有 **81 种写法**：`n.` / `adj.` 这类干净的占大头，但混着
`n.,adj.`（缺空格）、`det./pron./adv.`（斜杠）、`v., auxiliary v.`、
`indefinite article`、`prep., infinitive marker` 这些。直接拿字符串做筛选等于让用户在
81 个几乎不重复的格子里点，所以 `lib/listView.ts` 的 `posTags()` 把每条拆开、去句点、
再映射进 10 个大类：

| 数据里的写法                              | 归入 | 理由                                  |
| ----------------------------------------- | ---- | ------------------------------------- |
| `modal v.` / `auxiliary v.`               | v    | 情态助动词仍是动词，单独成档没人会用  |
| `indefinite article` / `definite article` | det  | 冠词是限定词的一类（见词性对照页）    |
| `prep., infinitive marker`                | prep | 只出现在 to，靠 prep 已能筛到，不硬塞 |

**混合词性按「命中任一」算**：`book`（`n., v.`）在「名词」和「动词」下都会出现。
如果按字符串相等筛，用户会以为词表里没有这个词。这是集合命中，不是前缀匹配。

### 首字母只在当前等级内生效

首字母是**普通筛选条件**，和词性、档位一样与等级叠加：

| 等级 | 首字母 | 结果                          |
| ---- | ------ | ----------------------------- |
| A1   | S      | 96 条（A1 里全部 s 开头的词） |
| A2   | S      | 113 条                        |
| 全部 | S      | 603 条                        |

想看全库某个字母，把等级选成「全部」——**跨不跨等级由等级条件说了算**，
不由字母说了算。这条曾经做反过：早先把首字母当「浏览入口」，选字母就自动
`ensureLevels("ALL")`、板块进度也跟着跳到全库，等于替用户改掉了他明确设过的
等级条件。停在 A1 的人选个 S 就被拉走了，与「只是其中一个筛选」的定位相反。

搜索是唯一跨等级的条件（搜 abandon 时不该被「当前停在 A1」挡住），
`lib/listView.ts` 的 `filterWords` 里只有它对等级做了特殊处理。

字母按钮给了 a–z 去掉 x：4955 条里没有一条以 x 开头，摆一个永远空态的按钮只是噪声。
`initialOf()` 本身仍按 `/^[a-z]$/` 判定，将来数据里出现 x 开头的词，只需把它加回
`INITIALS` 数组。

### 滚动与固定

外壳是 `h-[100dvh] flex flex-col`，顶栏 / main / 底部分页都不滚，滚动只发生在词表内部那一段
（`min-h-0 flex-1 overflow-y-auto`）。这样翻到第 40 行时搜索框和分页器都还在原位。

词表滚动的两个细节写在 `useScrollKeeper` 里，都是实测踩出来的：

- **必须用 callback ref**。滚动容器只在「加载完且非空态」时才渲染，用
  `useRef` + `useEffect([])` 会在首次 mount 拿到 `null` 且永不重跑，监听装不到节点上。
- **恢复后要压一帧屏蔽 scroll 事件**。面板重新可见时浏览器会把位置夹到 0 并补发一次
  `scroll`，不屏蔽它就会把刚写回去的位置又抹成 0（表现为「切页回来必回顶部」）。

翻页 / 换筛选时则主动 `reset()` 回顶部 —— 否则从第 3 页翻到第 4 页，人还停在上一页中间。

词表与词性对照都是**常驻**面板：第一次进入后一直挂着，切路由只切 `hidden`，每个面板自己滚。
所以从词性对照返回，筛选、页码与滚动位置都还在。挂在 window 上的快捷键（Shift+↑↓ 扩选）
由 `usePageActive` 门控，隐藏的页面不接键。

## 只出中文：先想，再看

筛选抽屉最上面一格是「显示」，只有两档：只出英文（默认）／只出中文。

**它不是中英对照。** 对照时眼睛先扫到英文，等于把答案印在题面上；切到中文后这一行
左半边只剩释义，英文藏起来，想看就点那一行（或按回车）当场揭晓。揭晓状态放在行组件的
`useState` 里，不进 `ListView` —— 它是这一屏的临时动作，翻页或换筛选就该重来；
持久化它等于让下次打开时答案全是摊开的。

中文态还会**撤掉行内的词典外链**：留着一个「点单词跳百度翻译」等于给答案。
揭晓之后链接才回来，那时它已经不再泄题。

揭晓状态**不能活得比这一轮中文态更久**。切回英文再切回中文时，行的 key 与 index 都没变，
`memo` 判定无变化不重渲染；若 `revealed` 只是个普通 `useState`，答案会原样摊着 ——
于是刚切进中文态就看到答案已经揭开了，这个功能当场失效。所以在渲染期按「中文态是否开启」
重置（比 `useEffect` 早一帧，看不到闪一下的答案）。`cn.revealResetsAcrossToggle` 钉住这条，
把重置逻辑删掉它会立刻变红。

释义单独成包（`src/data/zh-*.json`），与词表同序一一对应，按板块懒加载：

|          | 词表分包  | 释义分包    | 首屏要不要下 |
| -------- | --------- | ----------- | ------------ |
| A1       | 4.2KB gz  | 8.4KB gz    | 不下         |
| A2 / B1  | 3.8 / 3.3 | 7.7 / 7.1   | 不下         |
| B2 / C1  | 5.7 / 5.8 | 12.6 / 12.8 | 不下         |
| 五个合计 | 21.7KB    | 48.7KB      | —            |

**为什么不并回主产物**：并回去是 21.7KB → 73.6KB gzip（+52KB），每个只用英文的人
凭空多付；分开之后，首屏与「只出英文」这条路一个字节的释义都不碰。

**但要分清「首屏」和「装成 PWA 之后」。** 两份产物都在 `globPatterns` 里
（`**/*.{js,css,html,ico,png,svg,woff2,json}`），所以 SW 会在空闲时把释义分包
**一并预缓存**：装过一次之后，断网切中文照样有释义。实测确认过（断网 → 点筛选 → 只出中文 →
首行显示「一个；一名」，没有「暂无释义」占位）。代价是 49KB / 全量 precache 的 13%。

这个取舍是**故意留的**：把 `zh-*` 排除出预缓存很容易（加一条 `globIgnores`），
但那样离线时中文模式就只剩占位符 —— 而「装到手机上、地铁里背」正是这个 App 的主场景。
真要用英文的人，49KB 只在首次安装时下一次，不是每次打开都下。

**对齐是唯一的契约。** 释义靠下标对应词条，一旦错位就是把 A 的答案挂到 B 上 ——
这种错每个词都有释义、格式也正常，没人会一眼看出来。所以 `build-data.mjs` 写盘前
逐板块断言两份产物等长（不等长直接抛，构建失败），`loadGlosses` 长度对不上时返回空 Map
（少显示释义只是难看），`glosses.test.ts` 再钉一遍。

### 释义曾经撞车，修法是逐条改

中文一进界面，一批「同一条牛津英文定义 → 同一句中文」的合并结果就藏不住了。
最硬的四条是关节：`ankle / knee / elbow / wrist` 全是「踝；脚踝」。根因在抓取层——
`<span class="def">` 里还嵌着内层 span，正则把英文定义截成了 `the joint`，
而翻译阶段按「同一句英文 → 同一句中文」去重。

一共 26 组、58 条，逐条改成人能背的释义（`scripts/fix-glosses.py`，每组的划分理由写在
脚本注释里），顺手修了 `him` 的释义写成「她（宾格）」。修完还剩 192 组「同中文不同词」，
那是**真同义词**（`almost` / `nearly`、`enormous` / `huge`），不该硬造区分 ——
中文态下看到两行一样，本身就是「这两个我分不清」的有用信息。

## 词频序、中文搜索、易混词

### 词频序

排序第三档（字母序 / **词频** / 随机）。按 `Word.rank` —— ECDICT 的 frq/bnc 合成分 ——
从高频到低频。

为什么需要它：**字母序是词典排版的副作用，不是学习顺序**。同一个 A1 板块，字母序的头几个是
`a, an · about · above · across`，词频序是 `the · be · and · of · in`。前者只会让「今天背的 50 个词」
在真实文本里几乎撞不到。

**配「未掌握」用才成立**：纯词频序的头几屏是 the / be / and，早就认识。这一档的意义是
「先把最常用的那批过完」，而不是「从头开始背」。

它读 `rank`，而 `rank` 来自 `tiers.json` —— 首屏快路径不载索引，那时 rank 全是 0。
所以开了词频序就要等索引补齐，与档位 / 牛津筛选走同一条边界
（`orderNeedsIndexes()` + `firstPaintNeedsIndexes()`）。不这样处理的话，开屏那一帧
会先画出一份「顺序等于字母序、按钮上却写着词频」的列表。

`rank === 0` 兜底排到最后，而不是当成最高频 —— 否则索引缺失时，没分过档的词会顶到第一页。

### 中文搜索

输入含汉字（`/[\u4e00-\u9fa5]/`）按**释义**匹配，否则仍按单词匹配。

分流而不是「两者都查」：搜 `a` 时若同时匹配释义，会命中几百条含「一个」的词，把单词结果淹掉。
语言决定意图，比模糊匹配可靠。

这个能力**曾经有过又删了**（`5ba5d28 搜索只匹配单词，不再把释义当词条入口`），
当时的理由是「查词交给三方词典」。现在释义已经进界面了，那个理由不再成立 ——
在中文模式里看到「回答；答复」，想反查是哪几个词，只能靠这条。

释义没载入时中文搜索返回**空集**，不退化成「不过滤」。退化成不过滤会让用户以为搜到了全库；
空集至少诚实，同时界面会把释义补载，下一帧就有结果。

### 易混词

构建期把「共用同一句中文释义」的词归组，产出 `confusables.json`：**192 组 / 399 条**，
最大的一组 4 个词（`answer / reply / respond / response` 全是「回答；答复」）。

这些不是数据错误，是**真同义词**。但也正因为同义，单独背哪个都记不牢 —— 认不出是哪一个。
把它们摆在一起对比（discrimination training），干扰来自「相似」本身，比把每个词各背四遍有效。

筛选抽屉里「只出易混」一档筛出这 399 条；分组数据只在选中这一档时载入（4.6KB gzip），
不在首屏。没有集合时该筛选返回空集 —— 与中文搜索同一条原则，「不知道」不该表现为「全部命中」。

分组在**构建期**算，不在运行期：只依赖两份产物，运行期重算一遍纯属白费 CPU。

## 复核筛选与中→英 自测

### 距上次标记

抽屉里有一档「距上次标记」：不限 / 7 天以上 / 30 天以上，只对已标掌握的词有意义。
已掌握的行在窄屏以上会显示「N 天前」，让这个筛选有可核对的依据。

数据来自 `mastery.at` —— 那份标记时间**一直存着**，但此前只有云端合并读它，
界面从没告诉过用户「这个词是 40 天前标的」，于是「已掌握」是个没有下文的终点：
标完就再也不会出现在任何视图里，「昨天背过、今天想不起来」永远没有第二次接触的机会。

零新存储、零新算法。代价是固定间隔而不是个体化排期；对自学 5000 词，
固定间隔 + 到期清单能拿到 FSRS 大部分收益，成本是它的十分之一。**不把 FSRS 请回来**：
`31483e7` 删它删得对，而且它有个真实的失败模式 —— 断三周回来，队列积压成山，直接劝退。

### 中→英 自测

板块进度那一行右侧有一个「自测」：拿**当前筛选结果**出 10 / 20 / 30 道题，
题面只给中文，自己敲英文。

为什么不是选择题：四选一即使完全不认识也有 25% 蒙对，而蒙对和记住在数据上分不开 ——
用它当「学得怎么样」的尺子，量出来的是运气。中文给出、英文自己敲，蒙不出来。

判分只容忍「不该判错」的那几样：大小写、首尾空白、内部多余空格、尾随标点。
不做任何拼写纠错 —— 「差不多对」正是要抓出来的东西。`a, an` 这类并列写法任一个都对，
`ice cream` 这种短语整体接受（不按空格拆）。

答错的词当场**取消已掌握**，回到待背队列 —— 用的就是已有的语义，不新增「错题本」概念。

**键盘要能走完全程。** 输入 → 回车提交 → 再回车进下一题，三下都是回车。判定完成后输入框
用的是 `readOnly` 而不是 `disabled`：`disabled` 的元素不可聚焦，一提交焦点就掉到 `body`，
「再按一次回车」不成立，用户得每题去摸鼠标。`drill.enterAdvancesWithoutMouse` 钉住它。

**「能出题几个」要能说实话。** 释义是懒加载的，弱网下第一次点开自测时那份分包还在路上。
这时算出来是 0 个可用词 —— 若据此把「开始」置灰，用户看到的是一个灰掉、也不说为什么的按钮。
所以加载中报「正在载入释义…」且不禁用，`data-loading` 把两种状态分开；
一题都组不出来时**留在设置页**，不切到「0 题的成绩单」。

**落库的只有汇总。** 每轮结束往 `drills` 追加一条「时间 / 范围 / 题量 / 答对数」，
结果页据此显示「上一次：对 2 / 10 · 这次更好」，以及最近 5 次的可折叠列表。
逐题对错**不存** —— 回答「这周比上周记得牢吗」只要正确率，逐题对错要先设计一套
跨时间对比模型，而这一版还没有用它的地方。

不存的那半仍然成立：不排期、不做 FSRS、不在界面上给「学习曲线」那种需要长期样本
才能画准的图。界面上最显眼的数字（已掌握总数）依然不能当质量用 —— 它随心情膨胀；
能当质量用的是这条流水里的正确率趋势。

### 两个踩过的坑

**「再来一轮」必须换种子。** 原来写的是 `seed || Date.now()` 再
`setSeed(cur => cur || Date.now())` —— 那只在 seed 为 0 时赋值，于是再来一轮沿用上一轮：
题目一模一样（这还算轻的），更糟的是「已上报」的去重键也相同，第二轮根本不记录。

**去重键不能是 `done`。** `done` 会随重渲染反复为真，而 effect 依赖里又有 `summary`，
不加锁会把同一轮记很多遍 —— 第一版就是这么把「上一次」写成了「和刚才那次持平」。
现在用「这一轮真正用的种子」当去重键。

## 性能

全库 4955 词下实测：词表勾选一次 16ms（200 行/页）。

`WordRow` 的 `memo` 必须自定义比较函数：行状态里有会随父组件重建的值，浅比较会失效，
一页 200 行时那是 200 次无谓重渲染。

## 发布

构建产物在 `dist/`，推送 `main` 触发 `.github/workflows/deploy.yml` 发布到 GitHub Pages。
PWA 预缓存由 `vite-plugin-pwa` 生成，装一次之后断网可用。

### 版本更新

`registerType` 是 **`prompt`**，不是 `autoUpdate`：新 SW 装好后停在 waiting，
等页面决定何时接管。

- **什么时候检查**：页面回到前台（`visibilitychange` / `focus`）时主动
  `registration.update()`，30 秒内不重复发请求。
- **发现新版本**：弹窗让用户选「立即更新」或「稍后」。稍后只在本次会话生效，
  新 SW 已下载好，下次冷启动自然用上。
- **`clientsClaim: true` 必须显式保留**：切到 `prompt` 后插件不再自动加它，
  首次安装的新 SW 会停在 activated 却不接管页面（`controller === null`），
  首次装完就断网会白屏。
- **重载由我们自己做，不靠 workbox-window**：它的 `isUpdate` 在 `register()`
  那一刻用 `Boolean(controller)` 固化，本次会话若是首次安装，之后任何接管都会被判成
  「非更新」，只发事件不重载。见 `src/hooks/usePwaUpdate.ts`。

回归：`npm run test:pwa`（从 `dist/` 自己造 A/B 两份夹具，起临时静态服务器，
验证「前台检查 → 弹框 → 稍后不重载 → 立即更新后页面真的变新」）。需要先 `npm run build`。

### 版本标识

「关于」页的版本信息全部来自构建时注入（`vite.config.js` 的 `define`）：
`__APP_VERSION__` / `__BUILD_SHA__` / `__BUILD_TIME__` / `__BUILD_FINGERPRINT__`。

- `BUILD_SHA`：CI 里取 `GITHUB_SHA` 前 7 位，本地构建是 `dev`
- `BUILD_TIME`：构建时刻，界面按本地时区显示到分钟
- `BUILD_FINGERPRINT`：版本 + 提交 + 依赖内容的短哈希，同一提交重复构建稳定

拿到手机后对着「关于」看 sha 和构建时间，与 GitHub 上最新提交比对即可确认。
发版前记得把 `package.json` 的 `version` 递增，它同时供 manifest 与界面使用。
