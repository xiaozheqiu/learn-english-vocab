# 词表数据来源与校正

## 结论先行

`data/*.js` 的释义已**整批替换为牛津词典权威义项**，不再是旧金山/词霸数据。

| 指标                  | 替换前            | 替换后                            |
| --------------------- | ----------------- | --------------------------------- |
| 数据来源              | 金山/词霸系（旧） | **Oxford Learner's Dictionaries** |
| 义项总数              | 26,576            | **33,688**                        |
| 每条义项带词性        | ❌                | ✅                                |
| 每条义项带 CEFR 分级  | ❌                | ✅                                |
| 含 `vt./vi.` 旧式标注 | 787               | **0**                             |

| 词条覆盖              | —                 | **4955 / 4955**（100%）           |

## 一、原来错在哪

不是零星翻译错，是三层系统性问题：

**第 1 层：数据源是旧词典，义项排序按词源而非使用频率**

```
stock    树干，祖先      → 牛津第 1 义：库存；现货
stake    桩，炮烙刑      → 牛津第 1 义：股份；股本
browser  吃嫩叶的动物…   → 牛津第 1 义：浏览器
coup     砰然的一击，妙计 → 牛津第 1 义：政变
gut      剧情，内容      → 牛津第 1 义：肠；肠道
fairness 晴朗，光明正大   → 牛津第 1 义：公平；公正
```

`树干 / 炮烙刑 / 砰然的一击` 都是这些词最古老的义项，被旧词典排在了第一位。

**第 2 层：构建时义项被截断**

验证过截断规则：**84.3%** 的条目能精确复现「取第一行前 2 个义项」。4007 个多义词里，
**1771 个（44.2%）** 因此丢了后续义项。

**第 3 层：11 条短语全部按首词查词**

```
have to → 有，怀有        （查了 have）
next to → 近邻干扰         （查了 next，串到无线电术语）
used to → 使用过的，二手的  （查了 used）
```

## 二、现在怎么修的

**1. 从牛津官网抓原始义项**（`scripts/fetch-oxford.py`，可复现）

抓取规则是实测出来的，缺一条就漏数据：

| 规则                    | 例子                                              |
| ----------------------- | ------------------------------------------------- |
| URL 一律小写            | `I → i`，`April → april`，`TV → tv`               |
| 空格转连字符            | `ice cream → ice-cream`                           |
| 同形异义词分页          | `lead → lead_1 / lead_2`；`back` 有 4 个词性页    |
| 短语动词独立成页        | `consist-of` / `rely-on` / `ought-to` / `o-clock` |
| **按 pos 区块切分义项** | 每条义项归到它前面最近的 `<span class="pos">`     |

最后一条最关键。不做词性切分时，`about` 的介词语义和副词语义会混在一起，
`post` 只抓到 `prefix` 页（因此出现过「post = 在…之后」这种单义残缺）。

**2. 逐义项译成中文**，12330 条全部人工级校对，按牛津原文语义对应，不拼接旧数据。

**3. 按项目词条的词性过滤**：一个词条声明 `[n.]` 就只取牛津的名词义项。

# 顽固词（leech）机制

## 为什么需要

FSRS 本身不会放弃任何一张卡：一张反复忘记的词会被反复排到「明天」，
每天都要花 6–8 秒过一遍却始终记不住。`above` / `stake` 这类抽象词
在真实使用中反复忘 8 次很常见，它们会长期占据队列头部的到期位。

## 规则

| 参数                  | 值  | 说明                                   |
| --------------------- | --- | -------------------------------------- |
| `LEECH_THRESHOLD`     | 8   | 累计 `lapses ≥ 8` 判定为顽固词         |
| `LEECH_COOLDOWN_DAYS` | 30  | 冷却期内不进主队列，到期自动回来考一次 |

**判据用累计 `lapses` 而不是当前 `stability`**：stability 会被一次答对拉高，
而 `lapses` 只增不减，才真正反映「这个词反复记不住」。

**「降频」而非「毕业」**：与「已掌握」的 30 天冷却期同一思路 ——
冷却结束后 `isShelvedAsLeech` 返回 false，它会自己回到队列接受复考。

## 「重新学」的语义

`store.relearnLeech(key)` 只做三件事：`lapses = 0`、`due = 现在`、`scheduled_days = 0`。

**不清 `stability` / `difficulty`** —— 那两项记录的是「这个词对你有多难」，
清掉等于把 FSRS 的记忆历史一起丢掉，会让它重新按新词排期。

## 统计口径一致性

`computeStats` 里的 `dueToday` 必须与 `buildReviewPlan` 的取词口径一致：

- 被 leech 挡住的词 → 不计入 `dueToday`
- `extended` 档（未开启全库复习时）→ 不计入 `dueToday`

否则底部导航会显示「待复习 3」，点进去队列里只有 1 个，用户会以为复习页丢词。
这个 bug 在实现过程中真实出现过，已修复并写入注释。

# 分档校准：改用牛津官方词表

## 从「纯词频」改为「官方标记 + CEFR + 词频」三重条件

| 规则 | 判据                       | 结果           |
| ---- | -------------------------- | -------------- |
| 1    | `ox3000`                   | core（无条件） |
| 2    | `ox5000` 且首义 CEFR ≤ b2  | core           |
| 3    | 无 ox5000 且首义 CEFR ≤ b1 | core           |
| 4    | 无 ox5000 且词频 ≤ 3000    | core           |
| 5    | 其余                       | extended       |

**为什么不能只用官方标记**：官方表漏了 95 个常用词（`CD`/`DVD`/`policeman`/
`blank`/`gentleman`/`tape`），只看标记会把它们判成 extended，但它们都是 A1–B1 基础词。

**为什么不能只用词频**：会把 **938 条官方标记的核心词**误判成 extended，
包括 `autumn`（OX3K）、`thief`（OX3K）、`sailor`（OX3K）、`well-being`（OX3K）
这批初学者绕不开的词。

## 校准结果

```
core     4010      extended  1313
  A1: core  900  extended    0
  A2: core  872  extended    0
  B1: core  809  extended    0
  B2: core 1404  extended   23
  C1: core   25  extended 1290
```

**extended 档里 CEFR ≤ b1 的词为 0 条** —— A1–B1 全部留在 core，
这是校准正确的直接证据。1290/1313 是 C1 词汇。

## 官方标记覆盖

| 指标                | 数值       |
| ------------------- | ---------- |
| 唯一词              | 4955       |
| Oxford 3000         | 2974       |
| Oxford 5000（扩展） | 1914       |
| 两者皆无            | 95（1.9%） |

**结论：这 5323 条里有 98.1% 确实属于官方 Oxford 3000/5000。**

## 顺带修掉的三个真实 bug

**1. 同词不同词性共用同一份释义（316 个词）**

`close` 的四个词性条目（v./adj./adv./n.）全都写着「关上；关闭；合上」，
`book` 的名词和动词都写着「书；书籍」。根因是写数据时把「该词所有义项」
给了所有词性条目，没有按词性过滤。

修复后：

```
close   [v.] 关上；关闭  ||  [adj.] 靠近地；接近地  ||  [adv.] 近；附近  ||  [n.] 结束；终止
book    [n.] 书；书籍    ||  [v.] 预订；订座
spell   [v.] 拼写；拼成单词 || [n.] 一段（短时间）；任职期
```

**2. 牛津分页抓取不全**

`do` 抓到的是缩写页（`ditto` → 「同上」），`pan` 抓到的是组合形式页（「全；泛」），
`night` 抓到的是 `goodnight` 缩写页。这些词在牛津的主词条位于 `_1`/`_2` 分页：

```
do_1    (verb, 38 义)   → do 的正确内容
do_2    (auxiliary verb, 5 义)
pan_1   (noun, 7 义)
night_2 (noun, 18 义)
```

已补抓 19 个首义为非主词条页的词，修好 `do` / `pan` / `night` / `eight`。

**3. 释义过长与词条内重复**

初版每词取 3 个义项，平均长度 15.6 字，且有 276 条词条内义项重复
（`address → 地址；网址；地址`）。收紧为「最多 2 个义项 + 总长 ≤14 字 + 词条内去重」后：

```
平均 6.0 字   中位 5 字   最长 14 字   词条内重复 0
```
