## 1. 设计语言

### 1.1 方向

词表产品的视觉原型是**卡片目录 / 索引卡**：纸、墨、一条横线、右侧的状态栏。
所以这套设计的骨架是「纸 + 墨 + 一条有语义的栏」，绿色只作为**生命力的信号**（进度、选中、可行动），不做装饰。

三个刻意的选择：

1. **不用纯黑做正文**，用绿墨 `#10201B`——和品牌绿同色相，整页像印在同一张纸上。
2. **衬线只给单词**，界面文案全部无衬线。衬线在此是功能性的（词典惯例、区分「这个词」和「关于这个词的说明」），不是风格标签。
3. **状态用左栏 3px 表达**，不靠一堆彩色 Badge。一屏 20 行时，扫视左边缘就能判断哪些该复习。

- 红色只在「答错」「清空数据」出现。

### 1.4 形状、间距、动效

- 圆角：卡片 14px / 按钮 10px / 药丸 999px / 输入 10px。**分级，不统一**。
- 阴影仅两档：卡片 `0 1px 2px rgba(16,32,27,.04), 0 12px 32px -24px rgba(16,32,27,.35)`；浮层 `0 24px 70px -24px rgba(16,32,27,.35)`。
- 间距基准 4px；区块间 16/24；卡片内 16；列表行 12/16。
- 动效只两处：浮层开合 180ms `cubic-bezier(.22,1,.36,1)`；答题反馈 160ms 颜色过渡。`prefers-reduced-motion` 全关。
- 不做进场动画、不做 hover 缩放、不给每个卡片加过渡。

| 状态   | 左栏           | 文字标签                   | 含义                   |

| 学习中 | 浅绿 `#7FBFAA` | 「2 天后」                 | 已排期，间隔 < 21 天   |

## 4. 登录 / 锁屏

### 4.1 定位（必须说清）

这是**纯前端静态站，没有服务端**，所以 PIN 只是「挡住随手拿起你手机的人」的隐私屏，不是真正的访问控制：数据本身在 IndexedDB，打开 DevTools 就能看到。

因此设计上：

- 不承诺安全，界面上不写「加密」「安全」字样。
- **不拿 PIN 加密学习数据**（加密了忘密码就真丢数据，代价大于收益）。
- PIN 用 **PBKDF2-SHA256（随机盐，100k 次）** 存哈希，不存明文——避免「一看 localStorage 就知道密码」。
  实现有两条：安全上下文走 `crypto.subtle`，非安全上下文（http + 局域网 IP）走 `lib/sha256.ts` 的
  纯 JS 版本；两者对同一组 (PIN, salt, iterations) 输出完全一致，所以换 origin 也能继续解锁。
- 应用启动时**立即渲染锁屏**，不先闪一下内容。

### 4.2 流程

```
首次进入 ──▶ #/setup
             ├─ 设置固定 6 位数字 PIN（两次输入一致）
             ├─ 或「暂不设置」（写 meta.lockEnabled=false，直接进 App）
             └─ 完成后进 #/

再次进入 ──▶ #/lock
             ├─ 数字键盘（自建 3×4，不用系统 input，避免自动填充与键盘跳动）
             ├─ 6 个圆点显示已输入位数（定长，不随输入增长）
             ├─ 错误 → 抖动 + 剩余尝试次数（5 次后锁定 30 秒，纯前端计时）
             ├─ 「记住本设备 7 天」→ localStorage 存解锁令牌（哈希 + 到期时间）
             └─ 忘记 PIN → 「重置访问密码」：验证一次旧数据无关，直接允许重设，
                并在同屏说明「学习数据未被加密，重置不会删除数据」
```

- 解锁状态存 `sessionStorage`，同一标签页刷新不重复问；关掉标签页重新问。
- 自动锁定：可配（默认 30 分钟无操作）。`visibilitychange` 回到前台时若超时则回锁屏。
- 桌面端同样适用（PIN 输入框 + 回车提交）。

### 4.3 数据

`meta` store：

| key              | 值                                                   |
| ---------------- | ---------------------------------------------------- |
| `lockEnabled`    | boolean                                              |
| `pinHash`        | `{ salt: string, hash: string, iterations: 100000 }` |
| `lockGraceUntil` | number \| null（记住本设备）                         |

## 5. 功能规格

### F1 词表与批量选择（P0）

- 表头勾选框三态：未选 / 部分（`indeterminate`）/ 全选。
- 作用域：**本页**（默认）⇄ **全部筛选结果**。切换时浮条上明确写出数量（「将影响 5323 条」）。
- 跨页选择保留；切筛选条件时提示「已选中 N 条不在当前筛选内」并提供「清空选择」。
- 批量动作：标记已掌握 / 取消已掌握 / 反选 / 清空选择。
- 键盘：`Space` 切换当前行；`Shift+↑↓` 扩选；桌面 `Shift+单击` 区间选择。
- 已掌握行：`--brand-wash` 底 + 深绿粗左栏 + 释义降为 `--ink-mute`。

### F2 复习（P0，核心算法）

**队列构成**（纯函数 `buildReviewPlan`）：

1. 取 `due ≤ now` 且**未手动标记已掌握**的卡片，按留存率 R 升序（R 相同则逾期久的先）。
2. 再按每日新词额度补「从未评分」的新词。
3. 按单次题量（默认 50）截断。

**评分口径**：`ts-fsrs` 5.4.2，FSRS-5 默认权重，本地计算。

| 参数                | 值                           | 理由                                          |
| ------------------- | ---------------------------- | --------------------------------------------- |
| `request_retention` | 0.9（浮窗可调 0.8–0.95）     | FSRS 锚点                                     |
| `maximum_interval`  | 90 天（冲刺期，见 §12 修订） | 保证三个月内必定复查一次                      |
| `enable_short_term` | `false`                      | 背单词是日粒度，不要 1 分钟/10 分钟的当日循环 |
| 评分档              | again / hard / good / easy   | 与 Anki 同口径，将来可拟合参数                |

**交互**：卡片正面只有单词 + 词性；「显示释义」后出现释义与四档按钮；每档按钮上直接印下次间隔（`忘记 1 天 / 模糊 3 天 / 记得 8 天 / 很熟 21 天`），用 `previewIntervals` 现场算——所见即所得，不靠猜。

其它：进度条 `7/42`、支持撤销上一步（回滚 FSRS 状态与当日计数）、结束页给本次统计 + 「再来一轮」、无到期时显示「今天已清空」+ 下次到期时间 + 去测试。

### F3 测试（P0）

题型：`英→中` / `中→英` / `拼写`，可勾选启用。

**抽题权重**

```
w = (0.6 + 2.6 × 错误率) / √(1 + 作答次数 / 8) × 题型系数
题型系数：英→中 1.0 · 中→英 1.1 · 拼写 1.25
从未测过：w = 2 × 题型系数
```

**抽样**：Efraimidis–Spirakis 加权无放回（`key = rng^(1/w)` 取最大 N 个），接受种子 → 可复现、可单测。

**干扰项**：优先「同等级 + 同词性」，再同等级，再跨等级；去重（避免两个选项同义）。

**判分**：

- 选择题即时判定，错则高亮正确项；
- 拼写接受词条并列写法（`a, an` 任一个），忽略大小写与尾随标点；
- 结果：正确率、错词列表、「只练错题」。

**回写 FSRS**（关键：测试也是学习）：答错 → `again`；有提示/二次才对 → `hard`；一次答对 → `good`；拼写一次写对 → `easy`。

### F4 数据层（P0）

IndexedDB（`idb`），库 `ox5000` v1：

| store     | key   | 内容                                                            |
| --------- | ----- | --------------------------------------------------------------- |
| `mastery` | `key` | 手动「已掌握」标记                                              |
| `srs`     | `key` | FSRS 卡片（due/stability/difficulty/state/…）+ 测验 right/wrong |
| `reviews` | 自增  | 每次作答流水（可导出，供将来拟合 FSRS 权重）                    |
| `days`    | `day` | 当日复习数/对错数/新增词数                                      |
| `meta`    | `k`   | 偏好、锁屏、迁移标记                                            |

- **主键沿用旧规则** `等级|单词|词性[|序号]`，历史进度零迁移成本。
- 首次启动读旧 `localStorage["ox5000-mastered-v1"]` → 写入 `mastery`，旧键保留作备份。
- 导出 JSON（mastery/srs/days/prefs）、导入（覆盖式，二次确认）、清空（保留 meta）。
- 降级：隐私模式打不开 IDB → 内存态 + 顶栏常驻提示「本次进度不会保存」。

### F5 统计（P1，并入浮窗）

今日复习数 / 正确率 / 连续天数 / 已学数 / 全库平均留存率 R / 未来 7 天到期柱。

### F6 工程（P0）

- 全量 TS，`strict: true`、`noUnusedLocals`、`noUncheckedIndexedAccess`（算法层开启）。
- 算法层保持纯函数：`src/lib/{words,srs,quiz,session,date,db}.ts`。
- Vitest 覆盖：间隔单调性、到期判定、R 计算、加权抽样可复现、拼写判定、连续打卡、PIN 哈希。
- shadcn/ui 按需：`button input card badge checkbox tabs progress sheet dialog`。
- `components.json` → `tsx: true`；`jsconfig.json` 删除，换 `tsconfig.json`。

## 9. 验收标准

1. `npm run typecheck` / `npm run test` / `npm run build` 全绿，零 TS 报错。
2. 一页 20 条，点一次表头全选全部勾上；取消同理；切页回来选择仍在。
3. 作用域切到「全部筛选结果」时可一次标记 5323 条，刷新后仍在。
4. 复习队列只含 `due ≤ now` + 当日额度内新词；四档按钮印的间隔 = 提交后实际排期。
5. 同一词连续两次「记得」，第二次间隔 > 第一次。
6. 答错一次后该卡 stability 显著下降，到期回到 1 天内。
7. 同一随机种子两次生成同一套题；错词在下一套题中出现概率更高。
8. 首次进入出现设置向导；设 PIN 后关页面重开 -> 锁屏；输入错误 5 次锁定 30 秒；「记住本设备」后 7 天内不再问。
9. IndexedDB 中 `pinHash` 无明文；旧 localStorage 进度已导入且原键保留。
10. 断网刷新仍能背词。
11. 360px 宽无横向滚动，底部导航不遮内容，抽屉可完整操作。
12. 系统开启「减弱动态效果」后无动画。

### 第八轮：性能实测与优化

你说得对，这些都能优化。做法是先测再改，避免凭感觉动代码。

基准数据（全库 5323 词 / 5323 张卡 / 180 天记录 / 3000 已掌握）：

| 指标                | 优化前           | 优化后         | 手段                                                                     |
| ------------------- | ---------------- | -------------- | ------------------------------------------------------------------------ |
| `computeStats`      | 3.71 ms          | 0.53 ms        | ① `retrievability` 改闭式公式，省掉每卡 Card 对象；② 9 趟遍历合并成 1 趟 |
| 一页 500 行勾选一次 | 166 ms（长任务） | 16 ms @200 行  | ③ `WordRow` 加 memo + 按字段比较 status；④ 选中回调改稳定引用            |
| 切页渲染            | 250 ms @500 行   | 200 ms @200 行 | ⑤ `PAGE_SIZES` 上限 500 → 200（7608 → 3108 个 DOM 节点）                 |

三个值得记下的细节：

1. **`memo` 不够**。`status` 是 `statusOf` 每帧新造的对象，浅比较永远为假，
   500 行全部重渲染。必须传自定义比较函数按 `kind/label/rail` 比。
2. **回调引用要稳**。`useSelection.toggle` 原来把 `keys` 放进依赖，勾一次就换引用，
   memo 全部失效；改成用 ref 读当前集合。
3. **`computeStats` 的 `now` 不能进依赖**，否则每秒重算全库。改用「每分钟对齐的时间戳」
   做信号，跨零点仍能自己翻页。

`retrievability` 换公式后用 63 组 (stability, elapsed) 网格与 ts-fsrs 库实现逐值交叉校验
（误差 < 1e-7），防止公式漂移导致队列排序与留存率静默变味。

### 第十三轮：修「学完回测试只有 8 题」

上一轮把测试出题池限定为「学过的词」之后，出现一个隐蔽 bug：
复习 20 个词，回到测试页却只出 8 题。

根因不在测试页，而在**常驻面板 + 补抽 effect** 的组合：

- 测试页是常驻面板，隐藏时 React 仍会重跑它的 effect
- 补抽逻辑判断的是 `canBuild`（学过的词 ≥ MIN_POOL=8）
- 用户在复习页逐个学词时 `records` 每变一次就触发一次判断
- 学到第 8 个词的那一刻条件成立 → 当场抽了一套 8 道题并冻结
- 回到测试页时 `run.questions.length > 0`，不再补抽

### 第十六轮：筛选确认、板块进度、视图持久化

第十六轮反馈三条，都在「词表页的状态」上：

| #   | 反馈                                                      | 结论                                                                                                                                                                                   |
| --- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 筛选抽屉里点一下就改数据，应该点「确定」才执行            | 抽屉改草稿态（`FilterDraft`）：等级 / 掌握状态 / 每页条数都只进草稿，列表一行动不动；「确定」一次性提交，关闭 / Esc / 点遮罩全部丢弃。抽屉里给一行「按当前选择会剩 N 条 · 点确定生效」 |
| 2   | 看不出当前板块掌握了多少（例如 A1 是 2/1、3/10 这类进度） | 筛选条下方常驻「板块掌握进度」：`A1 已掌握 12 / 900` + 细进度条 + 百分比。分母固定是板块总词数，不吃搜索词、也不吃「已掌握/未掌握」筛选；搜索时自动改报全库（列表本来就跨等级）        |
| 3   | 从第 1 页切到第 3 页 / 刷新后筛选状态全没了，要重新点一遍 | 筛选条件 + 页码收进一个 `ListView` 对象并写 `localStorage`（`ox5000-list-view-v1`）。刷新、被系统回收后重进都还原；读到的值逐字段校验，非法字段单独回落                                |

#### 为什么草稿态要「打开时重置」

`onOpenChange(true)` 时把草稿重置为已生效条件。否则上一次关掉抽屉时残留的草稿，会在
下次打开时看起来像「当前条件」，用户点确定的就不再是他刚选的东西。

#### 为什么进度分母不吃筛选

拿 `filtered.length` 当分母的话：选「已掌握」时永远是 900/900，搜一个词时永远 0/1 ——
这个数字就只剩装饰作用。分母固定为板块总词数，进度才是一个可以跨天对比的量。

百分比另有一条兜底：有进度但四舍五入成 0% 时显示 `<1%`，否则标了一个词看着像没生效。

#### 纯函数下沉

过滤、视图解析、板块进度都放在 `src/lib/listView.ts`，不进组件，`listView.test.ts`
覆盖 11 条：非法等级回落、逐字段回落（等级非法不影响页码）、页码只收正整数、
搜索截断 80 字、搜索跨等级、搜索匹配释义、掌握筛选叠加、进度分母不吃筛选、空板块不产生 NaN。
